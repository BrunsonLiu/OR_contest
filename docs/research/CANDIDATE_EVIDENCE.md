## 2. Pivot B 的一页定义
**问题（暂定）**：在两梯队零售网络中，每个仓可配不同 SKU 集合；未配 SKU 的订单需求触发顾客确认并产生拣货工时与拒绝/返拣成本。如何联合选择开仓、各仓选品宽度与流量，使开仓、运输、库存与确认成本之和最小？

- 主体：平台（网络与选品）、门店（缺货与确认）、顾客（回复）。
- 信息：选品在需求前决定；缺货在执行中发现；回复异步，窗口与订单状态相关。
- 行动：开仓、每仓 SKU 集合、流量分配、确认处理。
- 评价：总成本；确认工作量单列，不折进缺货罚价。
- 必要机制：选品宽度同时影响缺货频率与确认成本，二者不能分开优化。

### 四项检查

1. **删去行业名称**：问题变成“带下游确认工作量的选品—网络联合设计”，不依赖生鲜易腐；应按零售/履约网络定位，不宣称冷链特有。
2. **冻结机制**：把确认成本设为 0，`assortment-check-20261027` 显示最优从“近仓、选品 0”变到“远仓、选品 8”（切换 1.5—2.0）；机制有决策后果。但这是两仓八 SKU 的线性玩具，参数方向依赖持有/运输设定。
3. **判别实例**：上述两仓八 SKU 可手算；只证明机制会改变设计，不证明文献缺口。
4. **机制—模型—算法—实验对应**：模型有选品宽度与确认成本；算法候选是分段线性 + Benders；实验应以确认成本扫描检验网络是否变。对应关系成立到“模型—实验”，算法尚未实现或验证。

## 4. 四项检查（B 单订单确认）

1. **删去行业名称**：问题是“带异步审批请求与任务生成的拣货路径”，不依赖生鲜易腐；应按即时零售履约定位，不宣称冷链特有。
2. **冻结机制**：冻结“回复生成/取消任务”退化为固定清单 + 随机等待；冻结“窗口”只剩期限约束。E1 的 504 个确定性实例中 320 个可交付集合不同，说明机制有决策后果。
3. **判别实例**：R=1 时 A→A′→B 可完成；R=5 时只能保一项；替代若预批准，两种时延同解。手算可核，E1 独立枚举 504/504 一致。
4. **机制—模型—算法—实验对应**：模型见 `docs/paper/MODEL.md`，实验 E1—E6 留证；但精确 DP 在 E6 被补全后的规则族 0/16 追平，**算法对应不成立**。

## 5. 四项检查（A 多订单共享替代）

1. **删去行业名称**：问题是“多订单争用一件替代品的分配与请求时序”，不依赖冷链。
2. **冻结机制**：取消共享（每单一件）后退化为独立订单；共享使分配与回复先后耦合。
3. **判别实例**：`confirm-shared-20261027` 的 12 个实例；规则族含访问子集、顺序、等待、分配时，完整 DP 0/12 更好。
4. **机制—模型—算法—实验对应**：四节点精确 DP 与规则族已实现；没有留下算法空间，**算法对应不成立**。
