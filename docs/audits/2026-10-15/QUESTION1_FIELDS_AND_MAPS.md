# 第六轮：问题一字段映射与地图核查

## Excel 与 CSV 对应关系

历史 Excel 均为静态数值，没有公式。只读核查未改写原文件；文件 SHA256、工作表名、字段和逐项数量比较保存在 [question1_workbooks.json](question1_workbooks.json)。

| 历史文件 | 当前 CSV | 键与字段映射 |
| --- | --- | --- |
| `Q1-result1.xlsx` | `仓网业务表现文件_cplex.csv` | 一行汇总；开仓数量、时效满足率含义相同，成本列在当前 CSV 增加单位后缀 |
| `Q1-result2.xlsx` | `仓库处置订单量文件_cplex.csv` | `Name`、`SKU` 对应相同键；`Qty` 对应 `Qty（单位：吨）`，但数量口径不同，不能只改列名 |
| `Q1-result3.xlsx` | `仓网供应关系文件_cplex.csv` | `Name`、`Customer`、`SKU` 为路线键；`Qty` 对应 `Qty（单位：吨）` |

汇总字段按顺序对应：

| Excel 标题 | 当前 CSV 标题 |
| --- | --- |
| 开仓数量 | 开仓数量 |
| 时效满足率 | 时效满足率 |
| 总物流成本 | 总物流成本（单位：万元） |
| 仓库之间的运输总成本 | 仓库之间的运输总成本（单位：万元） |
| 仓库到门店的运输总成本 | 仓库到门店的运输总成本（单位：万元） |
| 开仓总成本 | 开仓总成本（单位：万元） |
| 出入仓处置总成本 | 出入仓处置总成本（单位：万元） |
| 智能调度系统采购总成本 | 智能调度系统采购总成本（单位：万元） |

历史汇总成本为 1728.194565，修正实验为 1650.769939；处理成本分别为 151.1232、78.697182。历史成本列未在标题中写单位，比较时沿用赛题的万元口径；这些结果来自不同策略及费用口径，差值不能全部归因于某一项修正。

历史仓库表 16 条记录的 Qty 全部等于历史路线出库量的 **2 倍**（浮点误差范围内）。当前 CSV 的 16 条记录已独立核对，等于实际路线出库量。因此不自动转换旧 Excel 为当前基线，也不把两种数量直接拼接。供应关系中的 Customer 对仓库调拨表示仓库名称，对末段配送表示门店所在城市，不能一律当成门店名称。

`results/question1/Q3-result.xlsx` 实际是问题三的 204 条未来预测记录，含 7 个有效日期及尾部空列；它不是历史真实需求。为保持既有引用，本轮保留位置并在导航注明其含义，不将它接入问题一求解。

## 坐标问题与修正

三个问题一绘图脚本原先各自维护手工坐标表：19 个名称中有 8 个不在实际仓库表内，实际 20 个仓库中有 9 个名称没有对应。修正实验中的郑州仓因此被漏画，相关出库量为 1150.4 吨。

现在共用 `src/geography.py`，严格按 `df_wh.csv` 的 Location 关联 `df_loc.csv`，覆盖全部 20 个 CDC/RDC，排除工厂。重复键、缺失或无效坐标报错；CDC 不再使用手工指定的城市坐标。

地图标记尺寸按同图最大出库量缩放，避免原来上万平方点的标记遮住相邻地点；仅改变显示，不改变吨数。超时路线图不再为缺失目的地虚构偏移坐标。交互图去掉本机 D 盘资源路径，并为成本、开仓数量、时效百分比配置对应坐标轴。
