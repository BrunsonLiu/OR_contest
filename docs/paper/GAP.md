# Gap 草案：顾客回复生成任务与确认窗口

本文对应论文第二节，只写“最接近的研究处理了什么、剩下哪条决策关系”，不把“没找到同标题”当创新证据。阅读范围截至 2026-10-27，未读全文的条目明确标注。

## 2.1 拣货路径与执行中重优化

- **Lorenz、Otto、Gendreau（Networks，arXiv 2409.12619）**：在线订单到达下的批次、排序与路径重优化；干预式重优化可以在批次执行中改派空箱，并从拣货员当前位置重排路线。已读第 1.1、2.1—2.2 节。订单内容确定，新任务来自新订单，不来自顾客回复。
- **Giannikas 等（2017，IJPE）**：干预式拣货策略；第 3.4 节表 1 把缺货改路、顾客修改内容列为潜在用途，但第 3.3 节与第 4.2.1 节的策略和实验主要针对新到订单介入。已读作者稿第 3 节及第 4.1—4.2.1 节。

结论：执行中改派与当前位置重路由已经研究；这两项本身不能作为贡献。

## 2.2 等待、挂起与恢复

- **Chen 等（2019，ECRTS）**：自挂起任务的分段模型，执行—挂起—恢复，等待期间释放处理器。已读第 1—2 节。任务集合固定，没有空间位置和窗口关闭。
- **Fischer、Györgyi（2023，Annals of OR）**：同一作业两段任务之间有精确时滞，间隙可以处理其它任务。已读第 1 节正式定义。顾客回复通常只使后续任务具备开始条件，不能改写成精确时滞等式。
- **Bhowmick、Pazour、Dayarian（2024 工作稿）**：门店拣货的 MDP，同步等待时间随机，行动包括继续等待、放弃等待、返回集货点，波次内有期限。已读摘要、第 3 节及第 4.1—4.6 节。清单固定，替代品在接单阶段已确定。

结论：等待、放弃、期限与路径的组合已有明确模型；“回复还会新增或取消任务、窗口随订单状态关闭”不在这些模型里。

## 2.3 顾客响应、延迟反馈与在线匹配

- **Brubach 等（作者版）**：随机奖励下的在线匹配，顾客可依次拒绝/接受推荐，有限耐心主要体现为可查看商品数。已读 PDF 第 1—3 页。
- **Bekci（NeurIPS 2024）**：延迟选择的在线学习，反馈延迟且可截断；K 是展示集合大小，不是库存数量。已读正文第 3 节。
- **Laporte、Jagabathula、Corsten（2026 修订稿）**：接单阶段的个性化替代短列表；全文未取得，只读摘要。
- **US20220237530A1**：按距离与接受概率选择替代、预留库存、顾客选择后修改路径的技术披露。

结论：概率接受、延迟反馈、替代与路径联动分别有对应；它们不处理“回复到达后生成实体拣货任务，并且必须在窗口关闭前执行”。

## 2.4 平台流程证据

Instacart Connect 同一套官方文档确认：商品处理与顾客决定分开记录；拒绝后可提供另一商品并提示拣货员寻找；确认接口只在订单处于 `picking` 时可用；离开拣货状态后同一变更不能再修改；同一变更只能被回复一次。它没有给出未回复默认动作、结束拣货权限和回复时延。

## 2.5 剩余差异

把上面几类工作按要素拆开：

| 要素 | 已有对应 | 仍缺什么 |
| --- | --- | --- |
| 执行中改派与重路由 | Lorenz 等；Giannikas 等 | 新任务来自新订单，不来自执行结果 |
| 随机等待、放弃、期限 | Bhowmick 等 | 等待只推迟完成时点，不改变任务集合 |
| 等待期间继续工作、恢复 | Chen 等；Fischer、Györgyi | 无空间位置、无顾客分支、无窗口 |
| 替代选择与路径联动 | Laporte 等；US20220237530A1 | 替代在接单期确定，不处理执行中回复 |
| 回复生成/取消任务 + 窗口关闭 | 已读范围内未找到完整对应 | 仍需核对订单修改、返工与信息请求时点三条线 |

**Gap 表述**：顾客回复本身会新增或取消后续拣货任务，且可执行窗口随订单状态关闭；现有工作分别处理了等待、重路由和替代选择，没有把“回复改变任务集合”与“窗口关闭”一起放进执行中的拣货决策。

## 2.6 这个 gap 的边界

- 这是“已读范围内未找到对应”，不是“文献没有”。订单修改、返工、带信息获取的随机路径三条线仍需补查。
- 即使组合未被覆盖，也不等于值得写论文；必须证明它改变决策。E1 的 504 个实例显示冻结任务集或冻结窗口会改变可交付集合，但那是线状小实例。
- 组合可能是“把两个已知模型接起来”。E5 在二维、给基线同样跳过权后仍有 4/16 的差距，是目前最支持“不只是拼接”的证据，但频率不高。
- 因此本文的贡献必须落在“回复生成任务 + 窗口”这一结构上，并用同信息、同行动的基线比较；不能靠增加一个约束或换一个场景名称。
