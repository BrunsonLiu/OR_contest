# 开题卡 v3：生鲜订单拣货中的顾客确认

2026-10-27。v1（温度档＋MLOR）核实后撤回；A（MLOR 合同与冷链网络联合设计）经判别后也撤回；本卡转 B，并把四段骨架写全。B 在门店履约层，不在仓网设计层。

## 为什么 A 也撤

Santos 等（IJPE 2026）已经把“零售商定 MLOR 条款、供应商做运营决策”的双层结构做了。把选址/温度加进下层，只是换供应商的成本函数；联合与顺序的差异仍然是双重边际化，不是新的决策关系。判别例里的成本跳变只是一个非凸成本，下层的生产/交付决策同样可能有固定成本或档位。除非网络响应改变合同工具本身（例如零售商为网络容量付费），否则是扩展而不是新问题。故不立项。

## 一、背景

生鲜电商/即时零售：顾客下单后，门店拣货员按清单取货。缺货时提出替代品，顾客在手机上同意、拒绝或另选；回复到达前，替代品不能算已拣；订单进入结账后，确认接口关闭；门店有交接截止时间。拣货员可以在等待回复时继续拣其他商品，回复到达后再返拣。生鲜品的温区和保质期会让部分替代不可行，这一步先作为约束保留，不展开成温度模型。

## 二、Gap

| 最近工作 | 已处理什么 | 没处理什么 |
| --- | --- | --- |
| Chen 等（2019），自挂起任务 | 执行—挂起—恢复；等待期间释放处理资源 | 任务集合固定；无空间位置；无窗口关闭 |
| Giannikas 等（2017）；Lorenz 等（2024），动态拣货/重优化 | 执行中改派、从当前位置重排路线 | 新任务来自新订单，不来自顾客回复；无确认窗口 |
| Bhowmick 等（2024），门店随机同步等待 MDP | 随机等待、放弃、期限、路径 | 清单固定；替代在接单期已确定 |
| Brubach 等；Bekci（2024），在线匹配/延迟选择 | 概率接受、有限耐心、延迟反馈 | 不是实体拣货任务生成；无返拣与窗口 |
| Instacart Connect 文档 | 商品处理与顾客决定分开；确认只在 `picking` 期间可用；离开后不可修改 | 未回复默认动作、结束权限、回复时延仍缺 |

Gap 一句话：**顾客回复本身会新增或取消后续拣货任务，而可执行窗口随订单状态关闭。** 已读范围没有把这两条合起来处理的工作；但这也是组合，必须先证明它改变决策，不能只靠“没人做过”。

开题阶段用的判别例（已写入[研究设计](../research/PROBLEM_DISCOVERY.md)）：单拣货员，A 缺货、A′ 替代、B 另一商品；回复时延 1 分钟时 A→A′→B 可按时完成，回复时延 5 分钟时只能放弃 B 或 A′；若替代在接单期已确定，两种时延同解。说明“回复生成任务＋到达前不可执行”不是把等待写成常数能替代的。

## 三、故事线（从成本结构和第一性原理推）

一张订单的成本 = 行走与处理工时 + 迟交/缺失的损失。缺货发生时，拣货员可以：立即请求并继续、原地等、跳过。

继续的价值 = 省下的等待时间 − P(回复太晚，已来不及执行) × 缺失损失 − 返拣多走的距离。

经典自挂起排程把等待当成免费的挂起，并假定任务集合固定；它无法给“回复会新增一个位置上的任务”和“窗口在任务执行前关闭”定价。所以它会系统性地低估“先继续、后返拣”或“先请求、再走近路”的价值。

可证伪命题：回复时延确定且替代品在现有路线上时，完整策略与自挂起基线应同解；回复时延不确定且替代品偏离路线时，两者分叉。分叉区间随窗口长度、替代品距离、缺失损失变化。若在广实例上不分叉，故事线不成立，撤回。

## 四、模型骨架

- 主体：一个门店、一名拣货员、一张已承诺订单；给定交接截止 D 和确认窗口 C。
- 状态：拣货员位置、各订单行状态（未拣/已找到/待回复/已同意/已拒绝）、待回复请求及已等待时长、剩余时间。
- 信息：缺货在到达货架时发现；回复时延与选择随机；回复到达前不能执行；订单离开 `picking` 后窗口关闭。
- 行动：下一站；是否及何时发请求、提哪个替代；等待或继续；回复后返拣；规则允许时退款或结束。
- 目标：截止前可交付的商品价值 − 行走/工时 − 缺失/迟交损失；不凭空加满意度罚价。
- 形式：随机最短路径/MDP；小规模可精确枚举。

## 五、实验骨架

- 正确性：小实例枚举，手算或精确 DP 对照；固定回复分支时退化到确定任务拣货。
- 算法：同信息、同预算、同停止规则，比较自挂起基线（固定顺序＋即时等待）与改进策略。
- 机制：完整机制与冻结任务生成、冻结窗口两组消融；方案放回完整模型评价。
- 政策：回复时延分布、窗口长度、替代品距离、缺失损失四组敏感性；找分叉区间与无收益区。
- 数据：无真实回复日志时用透明合成分布，明确来源与假设；不把合成结果写成现场效果。

## 六、算法骨架

- 基线：固定拣货顺序＋即时等待；或自挂起排程＋路径。
- 改进候选：以待回复请求的年龄和位置为状态的 DP/标签算法；规模大时用 rollout 或状态聚合。
- 故事线对应：新增部件只处理“回复生成任务＋窗口”这一处；消融删掉它，基线仍在同一评价器下比较。
- 失败条件：同预算下没有稳定收益，或收益只在参数极端点出现，则不宣称算法贡献。

## 七、机制检查（2026-10-27，已完成）

实验 `confirm-instance-20261027b`：线状 4 节点、504 个参数组合的精确 DP，比较完整机制与两个冻结对照。

- 完整机制与“替代已预批准”在 279 个实例上可交付价值不同，最多差 2（两项商品都不保）；
- 432 个实例的预批准计划会在回复到达前取替代，按完整规则重放时违约；
- 单独收紧确认窗口（C<D）在 41 个实例上改变可交付价值；
- 回复时延 = 1 时差异为 0，符合“即时回复≈预批准”的边界。

`instances.csv` 的 504 行由 `tools/verify_confirm_instances.py` 用独立访问顺序枚举核对，0 不符。这只证明机制有决策后果，不证明新问题成立，也没有算法比较。记录见 `results/experiments/confirm-instance-20261027b/`。

### 策略比较（2026-10-27）

`confirm-policy-20261027`：162 个实例，回复时延取快/慢/长三组分布，拒绝概率 0 与 0.2。完整 DP 与两个可执行规则（原地等回复；先拣另一商品再回来）同信息、同截止比较。

- 完整 DP 在 31/162 个实例上高于较好的规则，最大差 0.24（两项商品总值为 2）；高于“原地等”44 次，高于“先拣再回”120 次。
- 差异集中在拒绝分支：q=0.2 时 30 个实例有差异，q=0 时只有 1 个。回复越不确定，固定规则越吃亏。
- 跨模型核对：把点质量分布代回确定性 504 行，0 不符；完整值不低于两个规则，0 违反；窗口放宽不降低完整值，0 违反。

这说明机制与策略差异存在，但幅度中等；要撑起算法贡献，需要更大实例和可扩展方法。当前没有真实回复数据，不能写成门店收益。记录见 `results/experiments/confirm-policy-20261027/`。

### 商品数扩展（2026-10-27）

`confirm-scale-20261027`：商品数 1—4，期限按各实例最后货架位置收紧（last−2、last−1、last+1），替代值 2、其它商品 1，拒绝概率 0 与 0.2，共 48 个实例。

- n=1：0/12 有差异；n=2：4/12，平均 0.158；n=3：12/12，平均 0.412；n=4：10/12，平均 0.313。
- 差距不随商品数单调增大，n=3 最高，n=4 回落；最大差 0.9（总价值约 3—5）。
- 这说明“多几个商品”本身不足以支撑可扩展算法；组合困难更可能来自多个待回复请求，而不是商品数。
- 仍是线状小实例，规则未调参，没有真实数据。

下一步应加第二个缺货点、第二个待回复请求，检验状态维度增加时完整策略与规则的差距；若差距主要来自并发请求，才谈状态聚合或 rollout。

### 两个并发请求（2026-10-27）

`confirm-multi-20261027b`：两个缺货点、两个替代、一个其它商品，六个节点；两个回复独立，拒绝概率 0 与 0.2，期限 8—10，窗口两种，共 12 个实例。

- 完整 DP 只在 4/12 个实例上高于较好规则，最大差 0.5（总价值 5）。
- “走完再回”规则在多数实例上接近完整策略；差距没有比单缺货点明显放大。
- 拒绝概率 0 与 0.2 各有 2/6 有差异，拒绝风险不是唯一来源。
- 线状顺序让“走完再回”很有效，并发请求本身没有自动制造更大的策略差距。

这条结果削弱了“靠并发请求撑起可扩展算法”的假设。下一步要么换二维布局、增加请求数，看差距是否放大；要么重新评估算法贡献，不先写 rollout。

## 八、风险与待核实

1. 业务参数：未回复默认动作、结束拣货权限、回复与返拣时间。官方文档没有，需平台规则或日志；拿不到就停在“差异待检验”。
2. 场景：B 在门店履约层，不在仓网设计层；如果论文必须留在仓网层，这张卡不适用，需要另找机制。
3. 生鲜属性：当前机制不依赖易腐；若论文标题强调冷链，必须有温区/保质期改变决策的证据，否则按即时零售履约定位。
4. 文献：D'Haen 等（2024）全文未读；订单修改/返工与信息请求时点两条线还需补查。

## 九、当前选择

截至 2026-10-27 的证据：机制差异存在（504 个确定性实例中 320 个不同；162 个随机实例中 31 个完整策略更好；48 个商品扩展中 26 个；12 个双缺货实例中 4 个；二维公平跳过权下 16 个实例中 4 个）。但把规则族补全到“等待时长、顺序、替代先取/后取、替代前最多拣 m 件”后，二维 16 个实例中完整 DP **0 个**更好。也就是说，之前的差距来自基线缺少停止选项，不是算法空间。

按项目标准，这条线的算法贡献目前不成立。若继续 B，必须找到有限规则族不能复现的结构，例如多个相关请求、共享替代库存、非平稳回复时延，或规则无法表达的状态依赖；否则应重新评估问题，不硬写算法。

需要区分“机制无效”和“线状几何太特殊”。在线状实例里，替代品就在缺货货架与其它商品之间，先走完再回来几乎不绕路，所以完整策略的优势小；二维布局里替代品可能偏离路线，返拣成本才会出现。当前负结果主要说明线状几何不足以检验算法，而不是机制不存在。

二维试算还暴露了一个基线公平性问题（试算未留证，故不引用数值）：访问缺货点要绕路时，完整策略可以选择跳过缺货点，而“逐点等待/走完再回”规则总是访问它，差距会被放大。这不是机制证据，而是基线被削弱。所有可执行规则都必须拥有与完整策略相同的“是否请求”行动；后续二维比较要先加阈值规则（按替代价值与绕路成本决定是否访问），再谈差距。

### 二维布局与公平跳过权（2026-10-27）

`confirm-grid-20261027`：4×4 网格，缺货点 A 在 (0,1)，替代 S 在 (3,3) 偏离路线，三个其它商品；所有规则都允许跳过 A。阈值规则族按“期望替代价值 / 额外绕路分钟”决定是否访问，并在同一批实例上取最好阈值（对基线有利）。16 个实例：

- 完整 DP 在 4/16 个实例上高于最强规则，最大差 1.0（总价值 5）。
- 拒绝概率 0 与 0.2 各 2/8 有差异。
- 这是目前唯一在“公平跳过权”下仍保留差距的设置；但差距频率仍低，且阈值规则只决定访问/跳过，不决定请求时点。

结论：二维几何加公平基线后，机制仍有约 20% 的价值空间；下一步应加“何时请求/走哪条路线”的简单规则，确认差距不是又被基线缺口撑出来的。

### 规则族补全后（2026-10-27）

`confirm-grid-rules-20261027` 给规则族加入等待时长 k、近邻/远邻顺序、替代先取/后取、替代前最多拣 m 件（m=0—3），并在同批实例上取最好组合。16 个实例中完整 DP **0 个**高于族内最好规则，最大差 **0**。D=8 的 0.8 差距由 m=2 的规则复现：先拣两件、再取替代，被拒则继续其余商品。

结论：E5 的 4/16 是基线缺少“替代前停止”选项，不是算法空间。按当前实例类，精确策略可以被有限规则族复现；**算法贡献不成立**。

- 走 B：先补二维/多请求判别，并给基线同样的“是否请求”权，再决定是否投入算法。
- 留在仓网层：当前没有通过缺口检查的候选；需要另找一个机制，不能把 A 或 v1 重新包装。
