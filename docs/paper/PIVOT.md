# 换向判别卡：B 线之后的三个候选

B（顾客确认拣货）的算法主张已在 E6 撤回：规则族补全后，二维 16 个实例中完整 DP 0 个更好。本文不再为 B 加实验，只列三个可换方向，每个都写清现实机制、gap、故事线和撤回条件，供选择。

## A. 多订单共享替代库存

**现实机制**：同一门店里两个订单同时缺货，替代品只剩一件；先被满足的订单占用，后到的只能退款或换目标。生鲜门店的替代品库存通常很浅，这个竞争真实存在。

**Gap**：拣货模型按单订单处理；替代确认模型也不处理多订单争用同一件替代。共享库存把“给哪个订单”变成分配决策，且分配取决于两个回复的先后。

**故事线**：共享件的价值应给边际损失更大的订单；但请求发得早的订单可能先拿到批准，造成“先到先得”与“价值优先”的冲突。规则族若只按顺序或价值分配，无法同时处理回复时序。

**最小检验**：两个订单、一个共享替代件、两个缺货点；精确 DP 对比“按访问顺序分配”“按价值分配”“先批准先得”三个规则。若规则族仍能复现精确值，撤回。

## B. 仓网选品与门店确认的耦合

**现实机制**：平台在仓网里决定每个仓配哪些 SKU；配得窄，门店缺货和顾客确认就更频繁。确认要花拣货员工时、可能被拒、产生返拣。仓网设计只算运输、开仓和损耗，没算下游确认工作量。

**Gap**：网络设计把缺货当作缺货率参数或直接丢失销售；门店履约把选品当作给定。两边都没有把“选品宽度 → 缺货频率 → 确认工作量”接起来。

**故事线**：多配一个 SKU 的边际收益 = 减少的缺货损失 + 减少的确认工作量；边际成本 = 仓储与库存占用。确认成本越高，最优选品越宽、仓越靠近门店；确认成本低时，集中化仍最优。可在成本结构上推出一个阈值。

**最小检验**：两仓、若干门店、若干 SKU；用缺货概率近似把选品宽度映射到确认次数；比较“忽略确认成本”和“计入确认成本”的最优选品/开仓。若网络不变，撤回。

**算法候选**：选品宽度与开仓是整数决策，缺货概率是非线性的；可用分段线性 + Benders（主问题选址/选品，子问题确认工作量）。这条最接近仓网场景，也最可能满足“新问题 + 算法”的要求。

## C. 同一顾客的回复相关性

**现实机制**：一个顾客对多个替代品的接受/拒绝相关（品牌、价格、饮食习惯）；一次拒绝会更新对后续替代的判断。

**Gap**：现有确认模型把每个回复当独立事件；拣货模型没有顾客类型的信念状态。

**故事线**：若拒绝相关，先问哪一件、是否继续问、被拒后换什么，都会改变；独立模型会低估连续拒绝的风险。可用 POMDP 的信念状态表达。

**最小检验**：两个替代、顾客类型二值、回复相关；比较独立模型与信念模型的策略。若策略一致，撤回。

## 选择建议

- A 最省事，但可能又是一次“规则族少一个选项”的循环，优先级低。
- B 留在仓网场景，耦合真实，算法有明确落点；代价是要补缺货概率和选品数据，模型比 B 大。
- C 方法上最干净，但偏 POMDP，离仓网场景远。

若只能选一个，我建议 B：它是目前唯一同时满足“仓网场景、真实耦合、算法有位置”三条的方向，且撤回条件清楚——计入确认成本后最优网络不变，就停。
